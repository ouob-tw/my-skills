# 新專案套用檢查清單

每一項都要有證據（自動測試、指令輸出或截圖）才打勾。沒做的項目在交付說明寫原因，例如「第 3 層不做：代理已擋國家」。

自動測試用假時鐘測期限與鎖定，用軟體 WebAuthn 驗證器（瀏覽器測試可用 Chrome DevTools 的虛擬驗證器）測 passkey。

## 1. 代理擋國家

- [ ] 從國外 IP 連任何路徑（`/`、登入頁、`.js`、`.png`、`/api/x.js`）都是 403。
- [ ] 從台灣 IP（例如手機行動網路）與內網連得到。
- [ ] 從內網帶偽造的 `X-Real-IP`、`X-Forwarded-For` 連入：代理紀錄與程式紀錄都是實際來源；轉給程式的 `X-Forwarded-For` 只有一個位址。
- [ ] 沒有資料庫時：國外與台灣公網都 403，內網照常；放回資料庫後台灣恢復。
- [ ] 更新程式：下載失敗、壞檔時舊檔不變、結束碼非 0、紀錄看得到；正常時替換並重新載入。排程寫明時區。
- [ ] 代理上的其他網站回應與改動前相同；代理介面重建設定後規則還在。

## 2. 程式只信代理

- [ ] 從允許清單外的位址直連程式的 port（登入頁、靜態檔、不存在的路徑）都是 403。
- [ ] 允許清單沒設定時只有本機能連。
- [ ] 從清單外直連並偽造 `X-Forwarded-For` 不被採用。
- [ ] 多層代理由右往左取第一個非信任位址；有一項不是 IP 時整串不用；`X-Real-IP`、`CF-Connecting-IP` 不被採用。
- [ ] 非信任來源送的 `X-Forwarded-Proto: https` 不算 HTTPS。
- [ ] 清單裡寫錯格式時程式啟動失敗。
- [ ] FastAPI：uvicorn 用 `--no-proxy-headers` 啟動；SvelteKit：沒設 `ADDRESS_HEADER`、`XFF_DEPTH`，用自訂伺服器擋靜態檔。

## 3. 程式內 GeoIP（有做才測）

- [ ] 外國 IP 擋、查不到國家擋、例外清單放行。
- [ ] 沒有資料庫時只放例外清單；資料庫壞掉時保留舊的 reader；替換後會重新開啟。

## 4. 兩步登入

- [ ] 只答對密碼拿不到登入 Cookie；第二步通過才有。
- [ ] 第二步 5 分鐘後過期（回 `second_step_expired`，不算失敗次數）。
- [ ] 沒設任何第二步時無法登入，而且回應不透露密碼對不對。
- [ ] TOTP：RFC 6238 測試值通過；前後一步可用、超過不行；同一組數字只能登入一次；登記時確認用的數字不能登入。
- [ ] TOTP 登記需要先輸入一組正確數字才生效；更換後舊金鑰的數字立刻失效。
- [ ] 改密碼、更換或清除 TOTP 後，其他已登入的 session 都失效。
- [ ] 真實瀏覽器走完「密碼 → TOTP」，手機與電腦寬度各一次。

## 5. Passkey

- [ ] 已登入時在設定頁新增 passkey，不需登記碼；新增後列得到。
- [ ] 同一台裝置再新增時，頁面說明「已有 passkey」（`InvalidStateError`）。
- [ ] 刪除後它不能再登入；刪除要先確認。
- [ ] 免密碼登入成功；沒有使用者驗證（UV）的簽章被拒。
- [ ] 當第二步可用；沒有 UV 的實體金鑰在第二步可用。
- [ ] 重送同一個簽章被拒；回答別的挑戰值被拒；挑戰值過期被拒。
- [ ] 設定頁的登記 token 只有發起的 session 能用。
- [ ] 用 http 或其他網址打開時：所有 passkey 端點回 `passkey_unavailable`，頁面只說原因、沒有可按的按鈕。
- [ ] 第一次設定（沒有任何第二步）時，主機登記碼流程可用：要密碼加登記碼、10 分鐘過期、只能用一次。設好之後登入頁不再出現登記入口。

## 6. 鎖定

- [ ] 連續 5 次密碼錯被鎖，回 429 與 `Retry-After`。
- [ ] 同一來源反覆「密碼對 → 數字錯」仍會被鎖；passkey 驗證失敗也算。
- [ ] 只有整個登入成功才清除計數。
- [ ] 同時送出一大批請求，也只拿到剩下的次數。
- [ ] 重啟服務後鎖定與失敗次數仍在。
- [ ] 經代理時以真實 IP 計數（兩個不同的真實 IP 各自計數）。

## 7. Session、Cookie、標頭

- [ ] 登入 30 天後、或 7 天沒使用後要重新登入（假時鐘）。
- [ ] 兩步登入上線前的舊 session 全部失效。
- [ ] 作廢與登出後下一個請求就 401；登出後按上一頁回不到後台。
- [ ] HTTPS 時登入 Cookie 有 `HttpOnly`、`SameSite=Strict`、`Secure`、`Path=/`、`Max-Age`；本機 http 沒有 `Secure` 也能登入。
- [ ] 從別的網站或主畫面捷徑打開時，已登入的人多一跳就進後台。
- [ ] 跨站的表單與 JSON 寫入請求被擋。
- [ ] 每種回應（頁面、API、靜態檔、403、轉址、錯誤頁）都有安全標頭；HTTPS 才有 HSTS；上傳檔案原本的 CSP 保留。
- [ ] 頁面功能沒被標頭弄壞（即時更新、上傳、內嵌元件）。

## 8. 登入前的回應與紀錄

- [ ] 所有不需登入的回應裡沒有家目錄、絕對路徑、內部網址。
- [ ] 每種事件的成功與失敗各寫一行，欄位齊全（事件、結果、失敗原因、真實 IP、裝置 ID、User-Agent）。
- [ ] 把整個測試過程的紀錄搜一遍：沒有測試用的密碼、數字、登記碼、Cookie、token、WebAuthn 內容。
- [ ] 瀏覽器回報的 WebAuthn 錯誤有記錄，超長或大量回報被擋。
- [ ] 使用說明寫明：怎麼登記與更換第二步、手機遺失怎麼辦（主機清除 TOTP、刪 passkey、作廢裝置）、紀錄在哪裡看、允許清單與信任代理怎麼設。
